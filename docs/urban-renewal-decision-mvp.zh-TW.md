# 老舊建築與都市更新政策資料查核決策支援 v1.0

方法識別碼：`urban-renewal-evidence-review-v1`。設定版本：`1.0.0`。

## 1. 政策問題與系統定位

本模組回答：「市府規劃研究團隊若只能完成有限件數的前期資料查核，應先確認哪些有來源支持的行政區資料問題，為什麼？」流程為觀察、驗證、調和、排序、比較、複核及匯出。每個候選是「行政區 × 行政資料查核問題」，不是一棟建物、一個投資標的或一件認定完成的更新案。

這是獨立政策研究 POC。既有不動產儀表板仍提供市場與城市脈絡；本模組增加文件證據、資料治理與行政程序解讀。選入清單表示應投入研究查核，不能解讀為政府將核准、建物有危險或更新必須優先施工。

## 2. 都市更新與危老重建程序差異

都市更新與危險及老舊建築物加速重建是不同法律及行政程序，申請、核准、里程碑、統計母體及資格要件必須分開。來源文字出現「危老」或「都更」，不足以判定個案適用哪一法律或是否符合資格。

「自行劃定更新單元核准」僅能支持該指定階段。它不表示都市更新事業計畫或權利變換計畫已核定、建照已核發、已開工、已完工、住戶同意或現行法律狀態已確認。會議議程及紀錄只能證明來源記載的程序，不以提案或討論推論通過。歷史法規清單也不能取代現行法規及主管機關確認。

## 3. 既有不動產資料探索功能

原有實價、價格及租金指數、行政區比較、人口所得、土地使用、建築使用執照、都市更新法規與資料更新狀態可協助建立背景。新模組使用獨立查核條件，不能把實價篩選條件誤認為所有模組的全域限制。

市場價格、土地使用及人口背景不參與建物安全或法律資格判定。使用執照僅重用已稽核的安全摘要，不為新模組全量下載物件明細，也不以地址、案名或人名模糊串接個案。

## 5. 既有建物存量與建照／使照資料的差異

既有建物棟數描述某統計期間的存量；建照及使照描述被記錄的行政核發流量。一筆使用執照可能涵蓋多棟、整體工程、增建或變更。近期核發紀錄並不是當前全體建物的抽樣，也不能由缺少近期執照推論拆除。

即使來源提供屋齡，也只能依官方統計單位及界線描述。30 年以上不等於危險，樓層不等於耐震能力。沒有驗證的行政區屋齡存量時，區級老化暴露維持不可用，不以人口、交易、使照件數或比例補值。

## 6. 都更核准更新單元案件的適用範圍

可使用的觀察是來源明確記載的指定案件及行政區。先檢查文號、日期、身分重複及區名；同案多列或多份文件不因此增加案件數。無法確認的身分保留資料問題，不以非官方比對修復。

「有核准指定、缺少可獨立驗證後續階段」是查核問題，不能改寫成未推動、延宕、失敗或沒有政府紀錄。部分期間沒有刊載的區也不是零案件。任何件數都不當作全市更新需求、符合資格建物總量或完工率的分母。

## 7. 資料治理與快照版本

沿用靜態資料架構：官方檔案 → Node.js 擷取及驗證 → 日期／單位／地理標準化 → 版本化安全彙整快照 → TypeScript 決策 → React → 情境與匯出。來源原文保留在受控原始輸入；新的公開分析快照不複製不必要的地址、所有權人或專業人員姓名。

再現資訊包含 dataset/resource ID、來源網址、原始檔 SHA256、來源發布／更新日、擷取時間、處理時間、schema、方法及設定版本、分析母體、單位、排除規則與限制。來源更新日、個案行為日、使照日期、下載日及快照產製日分別標示。相同稽核輸入與固定設定應產生相同分析結果；更新失敗保留最後有效快照及其真實日期。

本版 `publishedAt` 為未知（null），不把資源的最後異動當成發布日。B 的 `resourceUpdatedAt` 為 2024-06-13（官方資源 `last_modified`），與 2026-10-19 固定分析日相差 858 日；目錄 metadata 的 2026-09 更新或個案行為日不會取代這個資源版本日期。

## 8. 查核候選及優先順序方法

完整規則見 [方法文件](urban-renewal-decision-methodology.md)。五個獨立維度為來源完整性 `source_integrity`、狀態可追溯性 `status_traceability`、時間新鮮度 `temporal_freshness`、口徑可比較性 `scope_comparability`、地理完整性 `geographic_completeness`。每個候選每維最多一次；同一來源問題造成數個缺欄不重複加分。

必要來源、行政區、統計定義及適用期間有效才可排序。至少兩個獨立實質問題為 A 優先複核；一個為 B 例行複核；已驗證脈絡而無實質問題為 C 脈絡觀察。必要證據無法確認則為證據不足，明示排除而非列為低優先。

排序依序為層級、獨立問題維度數、獨立已驗證來源類型數、明確未解的狀態問題、固定語意的來源新鮮度、穩定行政區 ID 及問題 ID。核准件數不是單獨優先依據。資料新鮮度使用快照參照時間，不隨開啟網頁當天悄悄改變。

資源版本未知或距分析日超過 365 日產生一個新鮮度問題；同順位時已知且較舊的版本優先，未知日期不填造成極舊日期。區次序沿用 `DISTRICTS`，不按來源案件數排序。本版依 11 個有 B 來源紀錄的區各建一個 `designation_follow_up` 候選，均為 A，理由是後續階段可追溯性及資源版本新鮮度兩個獨立問題。

## 9. 查核容量與策略比較

容量提供不限、5、10 或正整數自訂值，計算單位為查核問題。先套用區、類別、證據品質及門檻，再依策略選取。候選不足時顯示實際可選數，不補造工作。

「證據缺口優先」採決定性排序前 N 件。「行政區均衡涵蓋」按已文件化固定區順序輪流取各區一題，保留區內優先次序。「來源調和優先」只選有具體身分、來源定義或行政階段調和問題的候選；沒有適合候選時明示空結果。

均衡策略的區佇列依各區最高順位問題排序，再逐輪各取一題；同順位沿用 `DISTRICTS`。本版每區只有一題，因此它與缺口優先的名次及入選名單完全相同。來源調和也選到相同母體，因各題均有待查的跨階段連結；不能宣稱策略已改善分配結果。

實際預設條件（全區／全類別、嚴格品質、門檻 C、納入 B、分析日 2026-10-19）有 11 個合格問題。容量 5 選中正、大同、中山、松山、大安 5 區，另 6 題因容量未入選；容量 10 再加入萬華、士林、北投、內湖、南港，留下文山 1 題。不限容量涵蓋 11 區。各情境皆只有 2 個不同問題維度、1 類已驗證來源，不把逐題加總誤稱為不同維度數。

指標包含合格／入選問題數、涵蓋區數、不同維度與來源類型、排除理由及策略差異。涵蓋更多區僅代表研究時間的地理分布，不能稱為更多居民受保護或更新分配更公平。

## 10. 資料缺口與假設敏感度

容量 5 與 10、缺口優先與均衡策略的比較需固定來源快照、法律定義、地理單位、候選母體、類別及資格規則。顯示穩定入選、新入選、移出、名次變化及其理由。

嚴格／寬鬆品質、來源增刪或不同歷史版本會改變資格母體，必須標成「不同證據範圍」。沒有真實可用的舊版來源時，版本敏感度維持不可用。未知狀態、缺年及全市與區級不相容資訊保持可見，不將敏感度當作建物狀況或更新可行性變化。

本版 B 已通過驗證，所以嚴格／寬鬆品質的實際入選結果不變；介面仍將品質假設變動標成不同證據範圍。移除使照脈絡只改摘要範圍、不改名次；排除 B 則沒有合格問題。容量 10 保留原 5 題、增加 5 題，沒有名次變動。只有一版已稽核來源，無法實測新舊來源版比較。

## 11. 決策摘要與再現方法

「都市更新政策資料查核建議摘要」支援 JSON 與 CSV，包含政策問題、官方來源、期間／地理、可用屋齡脈絡、區級涵蓋、法律程序、入選問題及理由、容量假設、敏感度、未解差異、缺少現況、主管機關待答問題及限制。保留足以還原選取的版本、雜湊及條件；CSV 需防止公式注入。

本版快照為 `public/data/urban-renewal-decision/snapshot.json`，來源品質檔為同目錄 `source-health.json`，稽核輸入及 provenance 位於 `data/raw/urban-renewal-decision/`。候選 ID 為「區名:designation-follow-up」，如 `中正區:designation-follow-up`。以 `buildReviewCandidates`、`runReviewScenario` 及 `compareReviewScenarios` 重現第 9 節容量比較，再以 `buildReviewBriefing`／`briefingToCsv` 匯出。`node --import tsx --test scripts/urbanRenewalDecision.test.ts` 含實際快照的 11 題與 5／10 容量驗證，完整命令及執行結果保留於進度紀錄。

模組沿用 Vite、React、TypeScript 及現有 Node test runner；不新增後端、資料庫、認證或套件依賴。前端按需載入獨立模組，保留中英文、鍵盤操作、窄螢幕、錯誤／重試、未知與空狀態，以及 GitHub Pages base path 相容性。PWA 的資料快取需隨快照版本驗證。

## 13. 不支持的建築安全及法律推論

本模組不產製個別建物危險分數、耐震／劣化推論、危險地址或負面建物排行，不依屋齡、樓層、執照年或地價推論拆除必要、更新資格、同意比例或投資價值。沒有官方精確座標就不畫物件點位。

不輸出所有權人身分，也不提供個人化法律、工程或投資建議。核准指定不是更新完工；使照不是當前建物存量；公開狀態缺失不是停滯證據。不得編造危險棟數、完工率、補助估計、受保護人口、開發收益或政府效率改善。

## 14. 後續擴充與資料需求

優先向主管機關確認可公開的區級既有建物屋齡統計、統計單位及修訂政策，並取得可驗證的跨階段穩定案件識別碼、官方狀態定義及更新頻率。需要官方明確區分都市更新與危老母體、指定／計畫／施工／完工各階段，以及數據缺漏代表未公開或不適用的規則。

若未來取得合法且語意完整的機讀資料，先新增稽核與回歸測試，再擴充候選。若要變更方法或資格，應提高版本並標示比較範圍變動。維持官方進度服務供人工確認，不把公開瀏覽頁面當作可任意大量擷取的介面。
