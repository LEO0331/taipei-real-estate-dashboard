# 臺北不動產與城市脈絡儀表板：決策洞察與技術設計說明

## 一、專案定位

這是一個以臺北市政府開放資料為基礎的探索型儀表板。它把實價登錄、住宅與商辦租售指標、都市計畫與土地資料、建照／使用執照、人口、所得、消費者物價、用電與若干公共資產資料整理成同一個可篩選、可比較的介面。

它的目的不是替使用者估價、預測價格或給出投資結論，而是縮短「取得資料、理解欄位、清理格式、交叉檢視脈絡」之間的距離。使用者應以它提出更好的問題，再回到主管機關公告、契約或專業意見完成查證。

## 二、可以支援的決策問題

### 1. 區域研究與初步盤點

在討論某行政區的居住、開發或公共設施議題時，可同時查看交易紀錄摘要、人口結構、所得、土地使用管制、建築執照及價格／租金指標。這有助於辨識資料之間是否存在值得追問的現象，例如：人口成長與建照量是否同步、交易單價變化是否與全市指數方向相近、土地使用管制是否限制了某些開發假設。

適合情境：

- 政策研究或社區議題的前期資料盤點。
- 不動產服務、都市規劃或研究團隊的區域背景整理。
- 內容團隊製作圖表、報告或公開說明前的資料核對。

不適合情境：

- 單一門牌、單一地號或單一建物的即時價格判定。
- 直接根據圖表做出買賣、授信、稅務、法律或投資決策。

### 2. 趨勢與脈絡比較

儀表板將月／季住宅價格指數、住宅租金指數、商辦租金指數、CPI、所得與用電等資料保留為獨立資料集，並以時間序列或區域摘要呈現。這種設計的價值在於比較「是否同向」、「何時開始變化」、「哪一層級的資料可支持觀察」，而不是把相關性誤當成因果。

例如，當住宅價格指數上升時，可進一步查看租金指標、所得或 CPI 是否也在變動；若沒有同步，也能避免過度簡化地用單一指標解釋市場。

### 3. 公共資料的行政紀錄檢視

專案亦涵蓋公告徵收清冊、市地重劃抵費地歷史標售、申報地價、經紀業名冊、估價師名冊、消費爭議與裁罰等資料。這些模組都將資料定位為「歷史或行政來源紀錄」，避免延伸成目前權利、營業資格、責任、可購買性或風險評分。

適合用於：

- 公共工程、地政資料與市場服務資料的歷史整理。
- 對資料欄位、涵蓋期間與來源限制的可視化說明。
- 需要保留資料原文、下載篩選結果、回溯來源的研究工作。

## 三、資料解讀原則

1. **來源欄位優先於衍生欄位。** 原始單位、日期、文字說明和識別碼會保留；坪數、每坪金額、比率等衍生值都有明確標示。
2. **缺失不是零。** 空白、破折號、無法解析的值維持缺失，避免把「沒有資料」轉成零而影響統計。
3. **資料集不被強制合併。** 經紀業名冊、裁罰與消費爭議分開呈現；同名不代表同一法律主體，也不應自動產生風險標籤。
4. **沒有官方座標就不畫點。** 地號、段小段與地址文字不會自動地理編碼，也不會產生看似精確但無依據的地圖標記。
5. **行政數值不等於市場價格。** 公告／申報地價、歷史得標價格、租金指標、稅率與公共資產紀錄各有行政意義，不能直接替代成交價格、估價或投資報酬。

## 四、2026-08 顧問檢視：可用洞察與決策護欄

### 1. 先把資料時間對齊，才討論「現在」

儀表板的資料不是同一時間點的快照。現有靜態檔中，實價登錄摘要最新到 **2026-05**、住宅價格月指數到 **2026-02**、建築使用執照到 **2026-05-29**；住宅價格季指數、住宅租金指數與商辦租金指數則到 **2025-Q4**；所得資料最新為 **2024**，年度 CPI 最新為 **2025**。這種時間差在公開資料整合中很常見，但會直接影響決策解讀。

**對客戶有用的做法：**

- 將最新交易資料視為較即時的「近期案例脈絡」，不要用它推翻較慢發布的指數。
- 在比較價格、租金、所得或 CPI 前，先確認比較的是相同或可接受的觀察期間；跨一年以上的資料只適合用於背景或結構性討論。
- 報告與簡報應寫明每個圖表的 `資料截至`，而不是只標示下載日期或網頁更新日期。

### 2. 「最高」與「最低」通常是在描述樣本組合，不是在排名地區

實價摘要目前包含 **998** 筆紀錄，其中 **556** 筆為買賣、**442** 筆為租賃；各行政區的筆數、產品類型、面積與屋齡組合並不相同。以某區的中位單價最高、總價最高或交易最活躍來下結論，容易把產品組合、豪宅或小樣本波動誤認為地區本身的價格差異。

**對客戶有用的做法：**

- 將「區域排名」改寫為待驗證的研究問題，例如「在相同房屋型態、面積區間、屋齡與期間下，差異是否仍存在？」
- 對低筆數的行政區、月份或產品類別，一律同時顯示樣本數；不以單月中位數作為趨勢判讀依據。
- 將買賣與租賃的資料與指標分開敘述；兩者的價格形成、揭露時點與樣本結構不同。

### 3. 市場訊號應採「三角驗證」，而不是單一價格結論

目前可作為有效的探索訊號，是觀察三條獨立但互補的線索：近期實價登錄、住宅價格／租金指數，以及供給與人口／所得背景。若三者方向不同，這不是儀表板失敗，而是提醒使用者不能把單一圖表解讀為完整市場敘事。

例如，2025-Q4 的住宅價格季指數顯示全市季變動接近持平（-0.02%）、年變動為負（約 -2.93%）；同期間住宅及商辦租金指數仍處於上升趨勢。這可作為「售價與租金不必同步」的研究起點，**不能**直接推出買賣時機、報酬率、租金收益率或未來價格方向。後續應回到相同期間、同一產品類型與正式來源資料核實。

### 4. 將地籍清理開標結果當行政個案，不當市場成交資料

地籍清理公告開標結果目前有 **35** 筆來源列、僅 **3** 筆可解析的決標金額；其餘大量列為「無人投標」或來源欄位空白。資料中的權利範圍、分列名義人與總底價欄位也使得同一地號可能有多列來源紀錄。

**這個模組能回答：** 特定地籍清理拍賣的行政結果、是否流標、來源記載底價與決標價的關係，以及哪些欄位需要人工檢視。

**這個模組不能回答：** 臺北土地供給、一般土地市場價格、現時可購買標的、目前所有權、土地投資價值或「便宜土地」排行。樣本過小且法律／權利背景特殊時，任何全市或行政區平均都只能作資料品質與個案研究用途。

### 5. 建照、使用執照、土地與公共資料最適合用作「查核清單」

建照／使用執照、社會住宅、都市計畫與土地使用管制資料，最有價值的用途是協助提出下一個查核問題：某區供給或公共工程是否值得進一步查證？資料涵蓋的年度、分類與行政程序是否一致？它們不是未來供給量、完工日、開發權利、可建面積或基地條件的保證。

若客戶要使用這些資料支持選址、公共政策、產品規劃或資本支出，建議把儀表板輸出列為「第一輪桌面研究」，並另行確認：法定土地使用、現行權利、工程期程、契約條件、現場狀況與主管機關最新公告。

### 6. 建議加入決策前的固定檢查點

在任何面向客戶、管理階層或外部利害關係人的結論前，至少確認：

1. 是否清楚標示每項數據的涵蓋期間、資料更新日與來源網址？
2. 比較的資料是否具有相同地理層級、產品範圍、單位與時間窗？
3. 是否同時呈現樣本數、缺失／排除筆數與已知資料品質旗標？
4. 是否把「描述性關聯」誤寫成因果、預測、估價、合規、現況權利或投資建議？
5. 是否已以主管機關、登記、契約、招標或現場資料完成關鍵結論的第二來源查驗？

### 7. 都市更新法規與市有財產資料：可作脈絡，不可當結論

新增的「都市更新相關法規」模組目前包含 **37** 筆來源紀錄（最早可解析紀錄日為 1997-07-30，最新為 2023-06-16）。它適合讓研究者用標題、來源類型和紀錄日期建立查核清單，再回到法規資料庫、主管機關公告或個案計畫確認現行效力與適用性。來源日期沒有被解讀為生效、廢止或修正生效日期，`ArticleType` 與 `CountyCode` 也只保留為來源值；因此不能據此判定個案是否符合都更資格、某法規是否仍有效，或某一基地可否開發。

「臺北市市有財產總目錄」提供 2021–2025 年、四種財產性質別與六種項目的 **120** 筆互斥明細列。2025 年有效來源列的加總為 **NT$11,629,803,009,818**，較 2024 年增加約 **NT$739.99 億**（約 6.8%）。這是行政／會計口徑下的來源列加總，可能反映取得、處分、重分類、會計處理或其他行政因素；它不是市有資產的即時市值、政府投資報酬、可出售資產總額或房地產市場漲幅。對財務、公共政策或資產治理討論最有用的問題是「哪一類來源列改變、何時改變、應向哪個機關查證原因」，而不是把年增減寫成資產升值或績效。

**對客戶有用的做法：**

- 對都更個案，將法規搜尋結果附在盡職查核清單中，另取得最新法規、都市更新事業計畫、權利關係與主管機關書面確認。
- 對公共資產簡報，同時列出來源年度、加總規則與「行政／會計金額」名稱；不要以市場估價、報酬率或可處分金額替代。
- 將兩個模組作為制度與行政脈絡，與實價登錄、價格指數、公告地價或租金資料並列，而非合併成單一「價值」或「投資」指標。

## 五、靜態資料發布與 PWA 快取的營運注意事項

本專案為可重現性而以 `public/data` 靜態 JSON 提供資料，且 service worker 會預快取重要資料檔。這適合公開展示，但也代表「更新檔案」本身不等於所有既有使用者立刻看到新資料。

- 每次更新資料集時，同步更新來源／涵蓋期間／擷取時間等 metadata，並在 UI 可見處顯示。
- 每次變更預快取的 JSON 或前端資產時，提高 `public/sw.js` 的 cache version；否則回訪使用者可能仍看到前一版快取。
- 發布前以無痕視窗或清除站點資料的方式驗證一次，確認新 metadata、JSON、CSV 匯出與前端顯示一致。
- 對失敗下載採「沿用舊檔」的流程時，必須明確揭露舊檔日期與下載失敗狀態，不可把舊資料標成最新資料。

### 優先改善事項（本次檢視）

1. **已完成：資料 JSON 已採 network-first 重新驗證。** 現行 service worker 對同源 `public/data/*.json` 優先向網路取新檔、成功後更新快取，僅在離線或請求失敗時回退快取。發布新資料仍應提高 cache version 並驗證 metadata、JSON 與 CSV 匯出一致，但「已快取使用者會永久停留舊資料」已不再是目前實作的主要風險。
2. **高優先：將資料新鮮度做成完整產品功能。** 現有「資料狀態與更新」頁已列出部分核心資料集，但尚未覆蓋都市更新法規與市有財產總目錄等新模組，也不是每一項都有來源更新日、下載日、產製日與下載失敗狀態。應擴充成全站資料狀態矩陣，並在跨模組圖表或洞察旁帶出實際比較時間窗。
3. **中優先：持續維持人名欄位的安全預設。** 地籍清理標售模組目前已採選擇性顯示、搜尋與匯出官方人名的作法；後續新增含姓名、聯絡資訊或識別碼的資料集時，應沿用此預設，禁止外部補充、人物檔案、關係推論與排行。
4. **中優先：對小樣本衍生圖表維持最低有效樣本門檻。** 地籍清理標售資料僅 3 筆有效決標金額，相關比較圖與摘要應持續顯示有效樣本數，並在低於門檻時改為資料品質提示或不顯示彙整結論；避免少數個案被誤讀為市場洞察。
5. **高優先：不要在所有頁面保留看似全域、實際無效的篩選器。** 目前主畫面的實價登錄篩選器會在多數專題頁面持續顯示，但只有實價資料表會使用它們。這可能使使用者誤以為已對公共資產、法規、地籍或指數圖表套用條件。應在非實價頁面隱藏、停用或清楚標示篩選作用範圍；每個專題頁只顯示自身有效的篩選條件。
6. **中優先：名冊的「現況」標示必須綁定資料快照日期。** 不動產估價師名冊以瀏覽器今天日期衍生 `valid`、`expiring`、`expired` 類別，但頁面沒有同時以同等明顯的方式揭露名冊快照日。對使用者而言，這容易看起來像即時執業資格判定。應改為顯示「依資料快照的期間欄位」或將狀態改稱為「來源期間已過／接近屆期」，並要求使用者向主管機關確認目前資格。
7. **中優先：避免單一資料檔失敗讓所有儀表板功能不可用。** 目前核心資料以單一 `Promise.all` 載入；其中任一 JSON 下載失敗時，連本來可獨立載入的專題頁也不會顯示。客戶在網路波動、CDN 部分失效或資料發布不完整時，會把「一份資料不可用」誤認成「整個儀表板沒有資料」。應改為模組層級的載入／錯誤狀態，保留其他已成功載入的頁面並清楚指出失敗的資料集。
8. **中優先：將資料與互動驗證納入發布門檻。** 現有測試集中於轉換器與純篩選函式，尚未自動驗證資料狀態清單是否涵蓋所有公開模組、可見篩選器是否真正影響目前頁面、或單一 JSON 失敗時的降級行為。發布前應至少檢查預快取 URL、資料狀態項目、篩選作用範圍與一個失敗請求的瀏覽器 smoke test，避免技術上的局部瑕疵變成客戶的錯誤判讀。

## 六、資料處理架構

資料流程可概括為：

```text
官方下載檔／人工放置的原始檔
        ↓
Node.js 擷取與格式辨識（UTF-8-SIG、Big5／CP950）
        ↓
轉換腳本：保留原文、解析日期與數字、建立資料品質訊號
        ↓
public/data 下的靜態 JSON 與摘要檔
        ↓
React 儀表板：依頁籤與需求載入、篩選、繪圖與 CSV 匯出
```

前端不在瀏覽器直接呼叫臺北開放資料 API。這讓展示結果較可重現、降低使用者開啟頁面時受到上游連線或跨網域限制的影響，也能先完成資料清理後再提供互動查詢。

## 七、實作過程中需要處理的問題與作法

### 1. 大型來源檔造成記憶體與載入壓力

**問題：** 建築使用執照 XML 等來源檔案很大。若一次讀入記憶體、完整轉為單一 JSON，再由瀏覽器全量下載，會同時增加轉換程序與使用者端的負擔。

**採用作法：**

- 在建置階段以 Node.js 串流解析大型 XML，而非先完整載入。
- 產生年度摘要與分年 JSON chunk。
- 前端預設只讀摘要；需要列表或細節時才載入相關年份區塊與明細。

**為何適合：** 儀表板的初始畫面通常只需要總量、趨勢與分布，不需要所有原始明細。將「摘要」和「明細」分層可直接減少首屏資料量。

**取捨：** 需要維護 manifest、分檔命名與按需載入邏輯；若使用者經常跨所有年份進行全文檢索，分塊會增加請求次數。

**可替代方案：**

- 若資料與查詢需求持續成長，可改以後端資料庫與 API 提供分頁、索引和聚合。
- 若需離線分析，可使用 Parquet／DuckDB-WASM 等欄式格式；代價是瀏覽器相容性、套件體積與操作複雜度會提高。
- 若資料量中等、互動要求極低，單一壓縮 JSON 的維護成本最低，但不適合大型明細。

### 2. 前端初始載入與 JavaScript chunk 警告

**問題：** 圖表元件與 React DOM 會讓單一 bundle 偏大，產生建置警告並延長首次下載與解析時間。

**採用作法：** 在 Vite 的 `manualChunks` 將 React、React DOM 與 Recharts／D3 相關依賴拆成穩定的 vendor chunk。

**為何適合：** 這些函式庫在多個頁籤重複使用，拆出後能讓瀏覽器快取共用依賴，也讓主程式 chunk 較小。它不改變產品功能或資料內容。

**取捨：** chunk 變多代表初次進入涉及圖表的頁面時可能多一個請求；在網路極差且使用者只會看單一頁面時，過度拆分未必更快。

**可替代方案：**

- 對少用的大型模組使用 `React.lazy` 進行頁籤級動態載入。
- 以較輕量的圖表元件或原生 SVG 取代部分 Recharts 圖表。
- 若部署環境有 HTTP/2/3、長效快取和使用者回訪，維持 vendor chunk 通常較有利；若是單次內網展示，則可依量測結果調整拆分策略。

### 3. 編碼、日期、單位與來源欄位不一致

**問題：** 開放資料常見 UTF-8-SIG、Big5／CP950 並存；ROC 年、Gregorian 年、日期字串、千元、平方公尺、坪、百分比及欄名標點也各不相同。

**採用作法：**

- CSV 讀取先嘗試 UTF-8，必要時回退 Big5／CP950。
- 統一的日期與數值解析工具以保守規則處理，無法確認的資料保留原文並標為缺失。
- 以別名比對欄位，容許合理的空白與標點變化。
- ROC 年只在格式足以確認時轉為 Gregorian；原始值同時保留。

**為何適合：** 這比「假設每份 CSV 都是同一編碼與 schema」可靠，且能把不確定性留在資料品質結果中，而不是悄悄製造錯誤數字。

**取捨：** 規則越保守，可解析筆數可能越少；但對公共資料儀表板而言，將未知呈現為未知通常比錯誤補值更可接受。

### 4. 識別碼與地籍編碼不能當一般數字

**問題：** 地號、登錄號碼、機關代碼、憑證字號與持分欄位可能含前導零、連字號或文字後綴。若轉成數字，會破壞辨識與比對。

**採用作法：** 原始識別碼以字串保存；只有在官方規則明確時才建立額外的顯示欄位。例如申報地價的八碼地號會保留 raw code，並以文件化 parser 轉成 `1` 或 `1-1` 形式供閱讀。

**取捨：** 字串欄位不能直接做數值排序；但保留資料語意比方便排序更重要。需要排序時應另建安全的排序鍵，而非覆蓋原值。

### 5. 對敏感或易被誤解資料維持安全邊界

**問題：** 裁罰、消費爭議、名冊、徵收、估價師與地籍資料很容易被錯誤延伸為「現況不合規」、「目前可買」、「有風險」或「市場價格」。

**採用作法：**

- 各模組明示資料期間、來源、限制與不適用事項。
- 裁罰、名冊與消費爭議不做同名自動合併與評分。
- 行政地價、歷史標售、公告徵收只顯示歷史／行政意義。
- 沒有官方座標與幾何資料時，不畫地圖點位與界址。

**取捨：** 少了吸睛的排名、風險分數與地圖互動；換來的是更可說明、較不誤導的資訊產品邊界。

## 八、可展示的使用流程

1. 先從市場總覽或價格／租金指數建立時間脈絡。
2. 以行政區比較人口、所得、建照、土地使用與交易摘要，找出需要進一步查證的差異。
3. 進入專題模組（如公共資產、地籍、服務業名冊或消費爭議）後，使用篩選器縮小資料範圍。
4. 下載當前篩選結果，保留分析條件並交由試算表、統計工具或正式研究流程續作。
5. 對關鍵結論回到官方公告、地政事務所、招標文件或主管機關資料查驗。

## 九、後續可擴充方向

- 建立資料來源更新狀態頁，顯示最後下載時間、涵蓋期間、解析成功率與欄位異動。
- 將共通的篩選、表格、CSV 匯出與資料品質元件抽成可重用元件，降低新增模組的重複程式。
- 若需要多人使用與大量跨資料查詢，可導入後端聚合 API、資料庫索引與權限／審計機制。
- 若要做正式決策支援，可補上資料版本、可重現查詢條件、引用格式與人工覆核流程。
- 將資料新鮮度、來源下載是否成功、快取版本與資料品質旗標整理成一個面向使用者的資料狀態頁，避免使用者把不同資料期間混作同一時點。

## 十、結語

這個儀表板的核心價值不是把複雜的城市與不動產議題壓縮成單一答案，而是讓資料來源、處理規則、衍生計算與限制條件被看見。當使用者知道一個數字從哪裡來、哪些地方不能推論，才更容易把它用在合適的研究、溝通與決策準備工作上。
